# MacroDeck ↔ Vesktop Local Bridge — Shared Protocol (Single Source of Truth)

> **Protocol version:** `1.0.0`
> This file MUST be identical in `macrodeck-plugin/PROTOCOL.md` and `vesktop-plugin/PROTOCOL.md`.
> Neither agent may invent a divergent protocol. If a change is needed, both copies must be updated together.
> All communication stays on the local machine. No cloud, no telemetry, no remote control.

---

## 1. Transport

- Transport: **WebSocket**, text frames only (UTF-8 JSON).
- Direction: **Macro Deck plugin = server. Vesktop plugin = client.**
- Defaults:
  - Host: `127.0.0.1`
  - Port: `8323`
- Bind rules (server):
  - Bind ONLY to loopback (`127.0.0.1` / `localhost`). Never `0.0.0.0`.
  - No LAN exposure unless user explicitly opts in via a setting (default OFF; out of scope for v1 — if enabled later it requires explicit UI + warning).
  - If port `8323` is unavailable, automatically try next free local port, and display the **actual bound port** clearly in Macro Deck settings.
- Framing:
  - One WebSocket text message = one JSON envelope (see §4).
  - Max message size: **64 KB** (65536 bytes UTF-8). Receiver MUST close/drop + log `protocol_error` (code `TOO_LARGE`) if exceeded.
- Keep messages small. Prefer IDs over names. Never send message content, DM content, tokens, or credentials.

## 2. Authentication — local token + session handoff

### 2.1 Token

- Macro Deck generates a cryptographically random token, **≥256-bit** (e.g. 32 random bytes, base64url or hex; min 43 chars base64url).
- Token is:
  - Stored locally in normal plugin settings area with normal OS user permissions.
  - Shown in Macro Deck settings behind a "Show" toggle, copyable, regeneratable.
  - **Never logged** (not even partially). Never sent except client→server inside `hello` on localhost.
- Regeneration invalidates all existing sessions immediately and disconnects the current client with `error` code `TOKEN_REVOKED`.

### 2.2 Handshake flow (normative)

```
Vesktop (client)                      Macro Deck (server)
     | -- WS connect to 127.0.0.1:port --> |
     | -- hello {v,name,version,token,capabilities} --> |
     |                                     | validate token, single-client check
     | <-- welcome {sid, heartbeatIntervalMs, v, requestSnapshot:true} -- |
     | -- state_snapshot + capability_update --> |
     | <-- get_state? (optional, if snapshot incomplete) -- |
     | <-- heartbeat_request / command ... -->  (steady state)
```

1. Vesktop connects.
2. Vesktop MUST send `hello` as its **first** message within 5 s of connect, containing:
   ```json
   { "v":"1.0.0", "type":"hello", "id":"<uuid>", "ts":1710000000000,
     "payload": { "protocolVersion":"1.0.0", "name":"vesktop-bridge",
       "version":"1.0.0", "token":"<secret, hello only>",
       "capabilities": { "<flag>": true/false, ... } } }
   ```
3. Macro Deck validates: JSON valid → size OK → `v` supported → token correct → single-client policy.
4. On success Macro Deck replies `welcome`:
   ```json
   { "v":"1.0.0", "type":"welcome", "replyTo":"<hello id>", "ts":...,
     "sid":"<session-id>",
     "payload": { "sessionId":"<same>", "protocolVersion":"1.0.0",
       "heartbeatIntervalMs":5000, "requestSnapshot":true, "readOnly":false } }
   ```
   - `sid`: server-generated random ID (UUIDv4, not a secret but do not log in full — log first 8 chars only).
5. Vesktop stores `sid`, includes it as top-level `sid` on all subsequent messages, sends `capability_update` + full `state_snapshot`. It MUST NOT send `token` again on that connection.
6. Both sides start heartbeat (§9). Macro Deck may send `get_state` if snapshot is stale/incomplete.

### 2.3 Auth failure

- On invalid token: reply `error` code `AUTH_FAILED` (no token echo), then close with WS code `4401`. Log only: `auth failure from 127.0.0.1 at <time>`.
- Rate limiting: max 5 failed attempts / 60 s per listener. After that, refuse new TCP accepts for 60 s (log once: `auth rate-limit engaged`).
- Version mismatch (`v` unsupported): reply `error` code `VERSION_MISMATCH` with `payload.supported: ["1.0.0"]`, then close `4400`.
- Second client while one authenticated: reply `error` code `ALREADY_CONNECTED`, close `4409` — unless user enabled "allow replacement" in Macro Deck settings, in which case old session is revoked with `error` code `SESSION_REPLACED` and new client proceeds.

## 3. Sessions

- `sessionId` (`sid`): random UUIDv4 generated by Macro Deck after successful auth.
- `sid` is NOT a long-term secret; it scopes one WS connection. Do not log in full (first 8 chars OK).
- Rules:
  - Token re-auth required on every new WS connection (reconnect = new `hello` with token).
  - Token regeneration kills all sessions.
  - Default: **one active authenticated client**. Setting `allowReplacement` (default false) permits a new `hello` to evict the old session.
  - Server tracks: `clientName`, `clientVersion`, `connectedAt`, `lastHeartbeat`, `capabilities`.
  - Client tracks: `sessionId`, `heartbeatIntervalMs`, `readOnly` echo.

## 4. Message envelope (normative)

Every message MUST be a JSON object with exactly these top-level fields:

| Field | Type | Required | Description |
|---|---|---|---|
| `v` | string | yes | Protocol version, currently `"1.0.0"`. Receiver rejects unknown major version. |
| `type` | string | yes | Message type (§5). Unknown → `error` `UNKNOWN_TYPE`. |
| `id` | string | no* | Unique message ID (UUIDv4 or `counter-random`). *Required* for `command`, `get_state`, `request_*`, `hello`. Recommended everywhere. |
| `replyTo` | string | no | Set on responses; echoes the request's `id`. |
| `ts` | number | yes | Unix epoch **milliseconds**. Receiver may drop messages >60 s skewed (log `protocol_error`). |
| `sid` | string | no | Session ID. Required on all client→server messages after `hello`; server→client includes it on `welcome`+ and echoes where useful. |
| `payload` | object | yes | Type-specific payload (may be `{}`). Never contains Discord tokens, credentials, or message bodies. |

Example `command`:

```json
{
  "v": "1.0.0",
  "type": "command",
  "id": "cmd-001",
  "ts": 1710000000000,
  "sid": "sess-abc",
  "payload": { "command": "toggle_mute", "args": {} }
}
```

Example `command_result`:

```json
{
  "v": "1.0.0",
  "type": "command_result",
  "replyTo": "cmd-001",
  "ts": 1710000000000,
  "sid": "sess-abc",
  "payload": { "ok": true, "command": "toggle_mute", "statePatch": { "selfMuted": true } }
}
```

Validation order: valid JSON → UTF-8 size ≤64 KB → required fields → known `type` → schema per type → auth/session check → rate limit. First failure → `error` (if connection is authenticated; otherwise close silently except `AUTH_FAILED`).

## 5. Message types

### 5.1 Vesktop → Macro Deck (client → server)

| Type | Payload | Purpose |
|---|---|---|
| `hello` | `{protocolVersion, name, version, token, capabilities}` | Auth + capability announce. First message only. |
| `heartbeat` | `{ok:true, discordReady:bool}` | Liveness. Interval per `welcome.heartbeatIntervalMs`. |
| `state_snapshot` | Full `State` object (§7) | Full state after connect / resync. |
| `state_update` | `{patch:{...changed fields}, seq:number}` | Incremental live update. `seq` monotonically increasing per connection. |
| `capability_update` | `{available:{flag:bool}, unavailableReasons:{flag:reason}}` | Feature support report. |
| `command_result` | `{ok:bool, command, args?, statePatch?, error?}` | Ack for one `command` (`replyTo` = command `id`). Always send, success or failure. |
| `error` | `{code, message, details?}` | Protocol/app error (§10). |
| `device_list_update` | `{inputs:[Device], outputs:[Device]}` | Audio device list push. |
| `channel_list_update` | `{guilds:[Guild], seq:number}` | Guild/channel list push. |

### 5.2 Macro Deck → Vesktop (server → client)

| Type | Payload | Purpose |
|---|---|---|
| `welcome` | `{sessionId, protocolVersion, heartbeatIntervalMs, requestSnapshot, readOnly}` | Auth success. `replyTo` = hello `id`. |
| `heartbeat_request` | `{}` | Optional ping; client replies `heartbeat`. (Either side may initiate; default: client pushes on interval, server times out.) |
| `get_state` | `{full:true}` | Request `state_snapshot`. `id` required; client replies with `state_snapshot` (`replyTo`). |
| `command` | `{command:string, args:object}` | Invoke one command (§6). `id` required; client replies `command_result`. |
| `request_capabilities` | `{}` | Request `capability_update`. |
| `request_channel_list` | `{}` | Request `channel_list_update`. |
| `request_device_list` | `{}` | Request `device_list_update`. |

- `error` may be sent by either side with the same envelope (`type:"error"`, `payload:{code,message,...}`).

## 6. Commands (normative names — use exactly)

`command` payload: `{ "command": "<name>", "args": { ... } }`. Unknown name → `command_result ok:false error.code=UNKNOWN_COMMAND`.
Unsupported (no capability) → `ok:false error.code=UNSUPPORTED` + ensure flag is false in `capability_update`.
Read-only mode (§6.2): control commands → `ok:false error.code=READ_ONLY`; state getters still work.

### 6.1 Command table (args; `*` = required)

**Connection / state (always supported if bridge online):**
- `refresh_state` `{}` → client re-reads Discord stores, replies + emits `state_update`/`state_snapshot`.
- `get_capabilities` `{}` → reply `command_result` with `payload.capabilities`, also emit `capability_update`.
- `get_channel_list` `{}` → emit `channel_list_update`.
- `get_device_list` `{}` → emit `device_list_update`.

**Mute / deafen:**
- `toggle_mute` `{}` · `set_mute` `{muted*:bool}` · `toggle_deafen` `{}` · `set_deafen` `{deafened*:bool}` · `toggle_mute_and_deafen` `{}` · `toggle_speaker_mute` `{}` / `set_speaker_mute` `{muted*:bool}` (speaker-mute maps to output mute where available; else UNSUPPORTED).

**Audio processing:**
- `toggle_noise_suppression`/`set_noise_suppression` `{enabled*:bool}` · `toggle_echo_cancellation`/`set_echo_cancellation` · `toggle_automatic_gain`/`set_automatic_gain` · `toggle_qos_high_priority`/`set_qos_high_priority` · `toggle_low_latency`/`set_low_latency` — same `{enabled*:bool}` shape for setters.

**Voice channel:**
- `join_voice_by_id` `{channelId*, guildId?}` · `join_voice_by_name` `{name*, guildName?}` · `join_voice_by_path` `{path*}` (`"Guild / Category / Channel"`) · `leave_voice` `{}` · `disconnect_voice` `{}` (alias of leave; force-disconnect) · `move_voice_by_id` `{channelId*}` · `move_voice_by_name` `{name*, guildName?}` · `move_voice_by_path` `{path*}` · `rejoin_last_voice` `{}` · `cycle_voice_channel` `{direction?:"next"|"prev"}`.
- Ambiguous name/path → `ok:false error.code=AMBIGUOUS` with `payload.candidates:[{id,name,path}]` (max 10). Not found → `NOT_FOUND`.

**Stage (best-effort; often UNSUPPORTED — report honestly):**
- `stage_raise_hand`/`stage_lower_hand`/`stage_toggle_hand`/`stage_request_to_speak`/`stage_cancel_speak_request` `{}`.

**Text channel:**
- `select_text_by_id` `{channelId*}` · `select_text_by_name` `{name*, guildName?}` · `select_text_by_path` `{path*}` · `select_last_text_channel` `{}` · `cycle_text_channel` `{direction?}` · `mark_selected_channel_read` `{}`.

**Status:**
- `set_status_online`/`set_status_idle`/`set_status_dnd`/`set_status_invisible`/`cycle_status` `{}` · `toggle_dnd`/`toggle_invisible` `{}` · `set_custom_status` `{text?, emojiName?, emojiId?, expiresAt?}` · `append_custom_status` `{text*}` · `clear_custom_status` `{}`.

**Devices:**
- `set_input_device_by_id` `{deviceId*}` · `set_input_device_by_name` `{name*}` · `cycle_input_device` `{direction?}` · `set_output_device_by_id` · `set_output_device_by_name` · `cycle_output_device` · `refresh_audio_devices` `{}`.

**Volume (ranges: input/output 0–100; per-user 0–200 where 100 = normal; attenuation 0–100):**
- `set_input_volume` `{volume*:0-100}` · `increase_input_volume`/`decrease_input_volume` `{step?:default 5}` · same trio for `output` · `set_user_volume` `{userId*, volume*:0-200}` · `increase_user_volume`/`decrease_user_volume` `{userId*, step?}` · `reset_user_volume` `{userId*}` · `toggle_user_local_mute`/`set_user_local_mute` `{userId*, muted*}` · `set_attenuation_volume` `{volume*:0-100}` · `toggle_attenuation_while_speaking`/`set_attenuation_while_speaking` `{enabled*:bool}`.

Timeouts: simple commands 3 s; voice join/move 10 s. On timeout Macro Deck surfaces `TIMEOUT`; Vesktop still sends late `command_result` if it completes (Macro Deck ignores if already timed out, keyed by `replyTo`).

### 6.2 Read-only mode

- Either side has `readOnly` bool (Macro Deck setting is authoritative; Vesktop echoes + enforces locally too).
- When ON: `get_*`/`refresh_state`/`request_*` allowed; all mutating commands → `READ_ONLY`.
- Macro Deck actions show disabled/unsupported when `readOnly` or capability missing.

## 7. State model (normative field names + types)

Full `state_snapshot` payload = object with ALL fields below (use `null` where unknown, never omit). `state_update.patch` = subset that changed.

```ts
type State = {
  // connection
  pluginConnected: boolean; authenticated: boolean; discordReady: boolean;
  bridgeRunning: boolean; lastError: string | null;
  protocolVersion: "1.0.0"; vesktopPluginVersion: string | null;
  readOnly: boolean;
  // voice
  selfMuted: boolean | null; selfDeafened: boolean | null;
  serverMuted: boolean | null; serverDeafened: boolean | null;
  voiceConnected: boolean; voiceConnecting: boolean;
  voiceChannelId: string | null; voiceChannelName: string | null;
  voiceChannelPath: string | null; voiceGuildId: string | null; voiceGuildName: string | null;
  lastVoiceChannelId: string | null; lastVoiceChannelName: string | null;
  // text
  selectedTextChannelId: string | null; selectedTextChannelName: string | null;
  selectedTextChannelPath: string | null; selectedGuildId: string | null; selectedGuildName: string | null;
  // status
  userStatus: "online"|"idle"|"dnd"|"invisible"|"unknown";
  customStatusText: string | null; customStatusEmojiName: string | null;
  // audio
  inputVolume: number | null;   // 0-100
  outputVolume: number | null;  // 0-100
  inputDeviceId: string | null; inputDeviceName: string | null;
  outputDeviceId: string | null; outputDeviceName: string | null;
  noiseSuppressionEnabled: boolean | null; echoCancellationEnabled: boolean | null;
  automaticGainEnabled: boolean | null; qosHighPriorityEnabled: boolean | null;
  lowLatencyEnabled: boolean | null; speakerMuted: boolean | null;
  attenuationVolume: number | null; attenuationWhileSpeakingEnabled: boolean | null;
  // stage
  stageHandRaised: boolean | null; stageSpeakRequested: boolean | null;
  stageIsSpeaker: boolean | null; stageChannelActive: boolean;
  // capabilities (echo of last capability_update)
  availableCapabilities: Record<string, boolean>;
  unavailableReasons: Record<string, string>;
};
type Device = { id: string; name: string; kind: "input"|"output"; isDefault: boolean };
type ChannelNode = { id: string; name: string; type: "text"|"voice"|"stage"|"category"; parentId?: string; path: string };
type Guild = { id: string; name: string; channels: ChannelNode[] };
```

- Volumes are numbers; booleans are strict `true/false/null` (never `"true"`).
- `lastError`: short human-readable code/message, no secrets (e.g. `"VOICE_JOIN_TIMEOUT"`, never tokens/IDs beyond channel/user IDs needed for the action — user IDs only in per-user volume commands, never logged verbosely).
- `lastVoiceChannel*`: updated on every successful join; used by `rejoin_last_voice` / `select_last_text_channel` (text side keeps its own last internally).

## 8. Capability flags (normative strings — use exactly)

Vesktop reports `available: Record<CapabilityFlag, boolean>` + `unavailableReasons: Record<flag, short reason>`. Macro Deck MUST NOT show an action as available unless its flag is `true`.

```
mute, deafen, speakerMute,

inputDeviceSelect, outputDeviceSelect,
inputVolume, outputVolume, perUserVolume, userLocalMute, attenuation,

```

Mapping hint (command → required flag): mute cmds→`mute`; deafen→`deafen`; speaker→`speakerMute`; NS/EC/AGC/QoS/LL→matching flag; join/leave→`voiceJoin`/`voiceLeave`; move→`voiceMove`; rejoin→`rejoinLastVoice`; cycle voice→`cycleVoiceChannel`; stage hand→`stageRaiseHand`; speak req→`stageRequestToSpeak`; text select→`textChannelSelect`; cycle text→`cycleTextChannel`; mark read→`markChannelRead`; status→`status`; custom→`customStatus`; input/output device→matching flag; volumes→matching flag; per-user→`perUserVolume`; local mute→`userLocalMute`; attenuation→`attenuation`; lists→matching flag. `refresh_state`/`get_capabilities` always available.

## 9. Live updates, debounce, heartbeat

### 9.1 Live updates (event-driven, no polling)

Vesktop MUST push `state_update` when any of these change: mute, deafen, server mute/deafen, voice connection/channel, selected text channel, status/custom status, input/output volume, input/output device, NS/EC/AGC, stage hand/speak, capabilities, channel/device lists, `discordReady`.

- Debounce: 100–250 ms coalescing window for rapid changes (e.g. volume drags). **Immediate** (no debounce) for discrete events: mute, deafen, join, leave, move, channel select, auth/session changes.
- `state_update` carries `{patch, seq}`; `seq` starts at 1 per connection, increments per update. Macro Deck applies patch to cache, refreshes button feedback, ignores out-of-order `seq` (log once at debug).
- After reconnect: full `state_snapshot` (seq reset), then `channel_list_update` + `device_list_update` if flags true.

### 9.2 Heartbeat

- Interval: `heartbeatIntervalMs` from `welcome` (default **5000 ms**). Timeout: **15 s** without any message (heartbeat or otherwise).
- Client sends `heartbeat {ok, discordReady}` on interval. Server may send `heartbeat_request`; client replies immediately.
- Missed timeout → mark peer offline, keep last-known non-live state, show disconnected UI, start reconnect (client) / await reconnect (server). Do not spam logs (one line per transition + debug for repeats).

## 10. Errors (normative codes)

`error` payload: `{ "code": "<CODE>", "message": "<short human-readable, no secrets>", "command?": "<cmd>", "details?": {} }`.
`command_result` failure: `{ ok:false, command, error:{code,message}, statePatch? }`.

Standard codes: `AUTH_FAILED`, `ALREADY_CONNECTED`, `SESSION_REPLACED`, `TOKEN_REVOKED`, `VERSION_MISMATCH`, `UNKNOWN_TYPE`, `SCHEMA_INVALID`, `TOO_LARGE`, `RATE_LIMITED`, `UNKNOWN_COMMAND`, `UNSUPPORTED`, `AMBIGUOUS`, `NOT_FOUND`, `READ_ONLY`, `TIMEOUT`, `VOICE_ERROR`, `PERMISSION_DENIED`, `DISCORD_NOT_READY`, `INTERNAL_ERROR`, `CHANNEL_FULL`, `ALREADY_IN_CHANNEL`.

- Never include tokens, session secrets (full), Discord tokens, cookies, message bodies in `message`/`details`.
- `unavailableReasons` values SHOULD be one of these codes or a ≤80-char reason.

## 11. Reliability

Must survive: Macro Deck restart, Vesktop restart/reload, plugin disabled, Discord not ready, wrong token/port, port conflict, WS drop, malformed/oversized message, unknown command, missing internal module, Discord update breaking internals, rate limits, command timeout, duplicate connections.

Rules:
- Never crash host. Never block UI thread — all WS/IO async.
- Reconnect: exponential backoff **1 s → 2 s → 5 s → 10 s → 30 s max**, jitter ±20 %. No tight loops. Log transitions at info, retries at debug after first.
- Commands: ACK every command (`command_result`), timeout 3 s (10 s voice join/move). Queue max 32 pending; beyond → `RATE_LIMITED`.
- Resync: full snapshot + capabilities + lists after every (re)connect.
- Rate limits (server): 20 msg/s sustained, burst 50 per connection; excess → `error RATE_LIMITED` then drop; sustained abuse → close `4408` + 60 s cool-down.
- Discord internals missing → adapter reports flag `false` + `unavailableReasons[flag]="INTERNAL_ERROR: <module>"`, commands → `UNSUPPORTED`; log `missing internal module: <name>` once at warn, rest at debug.

---

## 12. Security

- Localhost only. Token auth required. Session handoff after `hello` (no token replay).
- Validate everything; reject oversized/unknown/unauthenticated; rate-limit auth + commands.
- Logs sanitized: no tokens, no full `sid`, no Discord tokens/cookies, no message/DM content, no full dumps (channel/device/user lists only at debug and truncated to ≤10 entries with IDs only where needed).
- Prefer in-memory secrets; at-rest settings use host plugin-settings store with OS user permissions only. No network beyond `127.0.0.1:<port>`.
- Default-deny: unknown command → reject; missing capability → reject; read-only → reject mutating.

---

## 13. Logging (allowed / forbidden)

- Default level `info`. `debug` opt-in on both sides.
- Allowed at info: server started/stopped (+actual port), client connected/disconnected, auth success/failure (no secret), command failed (cmd + code), unsupported capability, protocol error (code only), reconnect attempt (attempt # + delay), missing internal module (name only).
- Forbidden always: token, full sid, Discord token, cookies/credentials, message/DM content, full channel/device/user dumps (debug-only, truncated).
- No log spam: coalesce repeats (e.g. heartbeat timeouts, volume floods) — one info line per state transition, rest debug.

## 14. Versioning

- `v` = `"1.0.0"` for this document. Minor additive changes (new optional commands/state fields/capability flags) bump minor (`1.1.0`) and MUST be backward-compatible (unknown fields ignored). Breaking changes bump major and require explicit handshake (`VERSION_MISMATCH` otherwise).
- Both plugins display `protocolVersion` + peer version in settings/status.

## 15. Minimal interop checklist (both agents must satisfy)

1. Server binds `127.0.0.1:8323` (fallback + display), rejects bad JSON/size/type/auth.
2. `hello`→`welcome(sid)`→`snapshot`→`heartbeat` works; bad token → `AUTH_FAILED` + close + rate-limit.
3. Every `command` gets one `command_result` (`replyTo` match) within timeout; unknown/unsupported/readonly handled with correct codes.
4. Discord-side mute toggle from Discord UI pushes immediate `state_update`; Macro Deck cache + button refresh.
5. Reconnect (either side restart) → backoff → re-hello → fresh snapshot, no crash, no log spam, no secret leak.
6. No non-loopback traffic; no polling hot loops; idle CPU ~0.

*End of shared protocol. Build order: protocol → structure → auth → heartbeat/reconnect → snapshot → mute/deafen → voice → text → status → volumes → devices → audio-proc → stage → lists → polish.*
